## 16.2 数据库性能优化

### 16.2.1 连接池调优

**当前配置：**
```yaml
spring:
  datasource:
    hikari:
      minimum-idle: 5
      maximum-pool-size: 10
      idle-timeout: 600000      # 10 分钟
      max-lifetime: 1800000     # 30 分钟
      connection-timeout: 30000 # 30 秒
```

**调优建议：**

| 场景 | maximum-pool-size | 说明 |
|------|------------------|------|
| 开发/测试 | 5-10 | 当前配置适用 |
| 生产低并发 | 10-20 | 适合 < 100 TPS |
| 生产高并发 | 20-50 | 需要配合慢查询优化 |

**计算公式：**
```
连接数 = ((核心数 * 2) + 有效磁盘数)
对于 CPU 密集型：连接数 = 核心数 + 1
对于 IO 密集型：连接数 = 核心数 * 2
```

### 16.2.2 SQL 优化

#### 16.2.2.1 慢查询示例

**问题 SQL：** 用户分页查询（联表）

```java
// 代码位置：SysUserServiceImpl.java:51-64
MPJLambdaWrapper<SysUserPO> wrapper = new MPJLambdaWrapper<>();
wrapper.selectAll(SysUserPO.class)
    .selectAs(SysPostPO::getPostCode, SysUserQueryVO::getPostCode)
    .leftJoin(SysUserPostPO.class, SysUserPostPO::getUserId, SysUserPO::getId)
    .leftJoin(SysPostPO.class, SysPostPO::getId, SysUserPostPO::getPostId);
```

**优化建议：**
1. 添加组合索引：`(user_id, post_id)`
2. 使用覆盖索引减少回表
3. 大数据量时考虑读写分离

#### 16.2.2.2 索引优化

**现有索引：**
```sql
-- sys_role 表
KEY idx_role_code (role_code)
```

**建议索引：**
```sql
-- sys_user 表
CREATE INDEX idx_user_mobile ON sys_user(mobile);
CREATE INDEX idx_user_org_id ON sys_user(org_id);
CREATE INDEX idx_user_status ON sys_user(status);
CREATE INDEX idx_user_update_at ON sys_user(update_at DESC);

-- sys_user_auths 表
CREATE UNIQUE INDEX idx_auth_identifier ON sys_user_auths(identifier, identity_type);
CREATE INDEX idx_auth_user_id ON sys_user_auths(user_id);

-- sys_menu 表
CREATE INDEX idx_menu_parent_id ON sys_menu(parent_id);
CREATE INDEX idx_menu_status ON sys_menu(status);

-- sys_log_login 表
CREATE INDEX idx_login_user_id ON sys_log_login(user_id);
CREATE INDEX idx_login_at ON sys_log_login(login_at DESC);

-- sys_tenant 表
CREATE UNIQUE INDEX idx_tenant_code ON sys_tenant(tenant_code);
```

### 16.2.3 分页查询优化

**当前实现：**
```java
IPage<SysUserQueryVO> page = sysUserMapper
    .selectJoinPage(Page.of(pagination.getPageNo(), pagination.getPageSize()), 
                   SysUserQueryVO.class, wrapper);
```

**优化建议：**
1. **限制最大页大小**：单页不超过 100 条
2. **深度分页优化**：使用游标而非 offset
3. **只查必要字段**：避免 SELECT *

**游标分页示例：**
```java
// 不推荐：深度分页
SELECT * FROM sys_user LIMIT 100000, 10;  -- 性能差

// 推荐：游标分页
SELECT * FROM sys_user 
WHERE update_at < :last_update_at 
ORDER BY update_at DESC 
LIMIT 10;
```

## 16.3 缓存策略

### 16.3.1 缓存架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   客户端    │────▶│  Caffeine   │────▶│    Redis    │
│             │     │  (本地缓存) │     │  (分布式)   │
└─────────────┘     └─────────────┘     └─────────────┘
                           │                   │
                           └────────┬──────────┘
                                    │
                           ┌────────▼────────┐
                           │    MySQL        │
                           │   (数据库)      │
                           └─────────────────┘
```

### 16.3.2 缓存类型

| 缓存类型 | 工具 | 用途 | TTL |
|---------|------|------|-----|
| **本地缓存** | Caffeine | 热点数据、配置 | 5-30 分钟 |
| **分布式缓存** | Redis | Token、会话、共享数据 | 根据业务 |

### 16.3.3 缓存配置

```yaml
pxc-framework-boot3:
  cache:
    type: redis  # redis / caffeine
```

### 16.3.4 推荐缓存内容

| 数据类型 | 缓存方式 | TTL | 说明 |
|---------|---------|-----|------|
| **用户 Token** | Redis | 2 小时 | Sa-Token 默认 |
| **系统字典** | Redis | 30 分钟 | 字典数据变化少 |
| **菜单权限** | Caffeine | 5 分钟 | 用户菜单缓存 |
| **组织树** | Caffeine | 10 分钟 | 组织架构树 |
| **系统参数** | Redis | 1 小时 | 配置参数 |
| **数据字典** | Caffeine | 30 分钟 | 本地加速 |

### 16.3.5 缓存更新策略

#### 16.3.5.1 Cache Aside Pattern

```java
// 读数据
public UserVO getUser(Long id) {
    // 1. 先读缓存
    UserVO user = cache.get("user:" + id);
    if (user != null) {
        return user;
    }
    
    // 2. 缓存未命中，读数据库
    user = userMapper.selectById(id);
    
    // 3. 写入缓存
    cache.set("user:" + id, user, 300);
    
    return user;
}

// 写数据
public void updateUser(User user) {
    // 1. 更新数据库
    userMapper.updateById(user);
    
    // 2. 删除缓存
    cache.delete("user:" + user.getId());
}
```

#### 16.3.5.2 缓存预热

启动时加载热点数据：

```java
@Component
public class CacheWarmup implements ApplicationRunner {
    
    @Override
    public void run(ApplicationArguments args) {
        // 预热字典数据
        dictService.loadAllDictsToCache();
        // 预热系统参数
        paramService.loadAllParamsToCache();
    }
}
```

### 16.3.6 缓存穿透/击穿/雪崩

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| **穿透** | 查询不存在的数据 | 缓存空值、布隆过滤器 |
| **击穿** | 热点 Key 过期 | 互斥锁、永不过期 |
| **雪崩** | 大量 Key 同时过期 | 随机 TTL、限流降级 |

**空值缓存示例：**
```java
public UserVO getUser(Long id) {
    UserVO user = cache.get("user:" + id);
    if (user == NULL_OBJECT) {
        return null;  // 缓存空值标记
    }
    if (user != null) {
        return user;
    }
    
    user = userMapper.selectById(id);
    if (user == null) {
        cache.set("user:" + id, NULL_OBJECT, 60);  // 空值缓存 1 分钟
    } else {
        cache.set("user:" + id, user, 300);
    }
    return user;
}
```

## 16.4 接口性能

### 16.4.1 接口分类

| 接口类型 | 示例 | P95 目标 | 说明 |
|---------|------|--------|------|
| **简单查询** | GET /get | < 100ms | 单条记录查询 |
| **分页查询** | POST /page | < 300ms | 列表分页 |
| **增删改** | POST/PUT | < 200ms | 写操作 |
| **复杂查询** | 联表统计 | < 500ms | 多表关联 |

### 16.4.2 优化建议

#### 16.4.2.1 减少 N+1 查询

**问题代码：**
```java
// 查询用户列表
List<User> users = userMapper.selectList(null);
for (User user : users) {
    // 循环查询岗位
    List<Post> posts = postMapper.selectByUserId(user.getId());  // N 次查询
}
```

**优化方案：**
```java
// 一次性查询所有数据
List<User> users = userMapper.selectList(null);
List<Long> userIds = users.stream().map(User::getId).collect(Collectors.toList());
Map<Long, List<Post>> postMap = postMapper.selectByUserIds(userIds)
    .stream().collect(Collectors.groupingBy(Post::getUserId));
```

#### 16.4.2.2 批量操作

**问题代码：**
```java
for (Long id : ids) {
    userMapper.deleteById(id);  // N 次 SQL
}
```

**优化方案：**
```java
userMapper.deleteBatchIds(ids);  // 1 次 SQL
```
